# Illumination normalisation

**Why.** Task 14 (D-48) found that a soft shadow over one third of the page escalated every document. The shaded
values vanished from the OCR text, while page confidence stayed at 0.92. The clean-up passes Tesseract a grayscale
page, and Tesseract binarises it with one global threshold. A region at 40 % brightness falls entirely on the "ink"
side of that threshold.

**What changed** (`src/lib/ai/preprocess.ts`, `normalizeIllumination`, on in `OCR_PIPELINE`, prep version `prep-v2`):
1. Before deskewing, estimate the paper brightness everywhere: the maximum over 32 px blocks, dilated across 3 × 3
   blocks so a heading glyph never fills a window, then smoothed and bilinearly upsampled.
2. Divide by that estimate. Paper becomes white everywhere, and ink keeps its contrast against the paper around it.

A uniformly lit page passes through unchanged.

**How it was measured.** The A/B below uses no model. It covers the same 20 documents and capture arms as
`docs/PERSPECTIVE.md`, OCR'd without and with the step, and reports:
- **CER**, the character error rate against the renderer's own transcript;
- **critical values found**, by the grounding matchers;
- **R-14 / R-19 and auto-clears** with the **known-good** extraction substituted for the model's. This shows whether the
  real rules notice what OCR lost. R-19 cannot fire in that setup, because a known-good value is never "absent".

One live run on the shadow arm confirms the end-to-end effect.

## Result

**The shadow is fixed, and nothing else regressed.**

Pipeline: illumination normalisation off / on per row (D-52), rectification off (D-50). OCR clean-up `prep-v2` with the normalisation switched per row.

| Shadow arm | CER | Critical values found | Known-good extraction |
|---|---|---|---|
| Illumination off | 30.7 % | 20 % | escalated 20/20 |
| Illumination on | 3.9 % | 100 % | auto-clears 20/20 |

The live run confirms it end to end: 20/20 bad becomes 0/20 bad, with 100 % field accuracy.

- **Clean scans:** identical.
- **Low contrast with JPEG blocking:** 4.0 % → 4.3 % CER, with every value still found.
- **Clutter:** unchanged. It is occlusion (a mug over the header), not light.
- **Unrectified photos:** move by one document either way, which is noise. Uploads are rectified first (D-50).

**Calibration, as a data point.** With the shadow and no normalisation, a third of each page was missing from the OCR
text, yet mean page confidence was 0.922, the same as the clean scan. Page confidence does not say a region was lost,
which is why the rules check the values themselves (grounding, R-14) rather than trusting the number.

**Known limit.** Right at a **hard** shadow edge, the paper estimate lags by up to about 1.5 blocks (≈ 50 px at the
working resolution), because the max window still sees lit paper across the edge. A unit test pins this. Real
shadows, and the benchmark's, have a soft penumbra.

Reproduce:

```bash
pnpm bench:illumination
```

This is model-free, cached under `.bench-cache/ocr-harness/`. Add `--live` for the one live check (at most 20 calls).
